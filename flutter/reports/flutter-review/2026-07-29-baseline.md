## P0 — Architecture Violations

### P0-001: No data/repository layer
**Files:** `lib/features/*/presentation/*.dart` (all 7 screens)
**Description:** Every screen calls `widget.session.api.get/post/getList()` directly. There is no `Repository` or `Service` layer between presentation and network transport.
**Impact:** Impossible to unit test screens without mocking HTTP. Cannot add offline caching without modifying every widget. Dependency Inversion Principle violated in 6 of 7 screens.
**Created by:** Initial implementation
**Tracker:** `mismatch-report.md` — Mismatch 3

### P0-002: Offline-first architecture not implemented
**Files:** `pubspec.yaml` (sqflite_sqlcipher declared but unused), no offline code exists anywhere
**Description:** HBT's core architecture principle is Offline First. The backend has a full offline sync API (`/api/v1/organizations/{id}/sync/bootstrap/`). The Flutter client has zero offline capability.
**Impact:** Cannot operate without connectivity. Violates base architectural constraint.
**Created by:** Not yet implemented
**Tracker:** `mismatch-report.md` — Mismatch 1

## P1 — Maintainability Issues

### P1-001: SessionController violates SRP
**File:** `lib/features/auth/application/session_controller.dart`
**Description:** Single `ChangeNotifier` manages: auth status, user profile, organization list, active organization context, permission checking, session persistence (secure storage), and sign-in/sign-out/restore flows.
**Evidence:** 185 lines, 8 public fields, 5 public methods, 3 private methods — 4 distinct responsibilities.
**Recommendation:** Split into `AuthService` (login/logout/token), `OrganizationService` (list/switch org), `PermissionService` (hasPermission checks).

### P1-002: Duplicate error card pattern (5 copies)
**Files:**
- `lib/features/cargo/presentation/cargo_acceptance_page.dart` (line ~90)
- `lib/features/cargo/presentation/cargo_worklist_page.dart` (line ~120)
- `lib/features/ticket_sales/presentation/counter_booking_page.dart` (line ~150)
- `lib/features/ticket_sales/presentation/payment_decision_page.dart` (line ~100)
- `lib/features/ticket_sales/presentation/ticket_sales_page.dart` (line ~80)
**Pattern:** `if (_error != null) Card(color: errorContainer, child: Padding(12, child: Text(_error!)))`
**Recommendation:** Extract `ErrorCard` widget.

### P1-003: Duplicate loading state pattern (7 copies)
**Files:** All 7 screen files
**Pattern:** `const Center(child: CircularProgressIndicator())`
**Recommendation:** Extract `LoadingIndicator` widget.

### P1-004: Duplicate try/catch/finally boilerplate (15+ instances)
**Files:** Every feature screen, 2-4 instances per file
**Pattern:** `_loading = true; _error = null; try {...} on ApiException catch (e) { _error = e.message; } finally { _loading = false; ... }`
**Recommendation:** Extract `AsyncState<T>` base class or `Result<T>` type.

### P1-005: API client has 95% duplicated request methods
**File:** `lib/core/network/api_client.dart`
**Description:** `_request()` (lines 34-95) and `_requestList()` (lines 102-165) differ only in return type assertion (`Map` vs `List`). Both implement the same: headers, auth, timeout, error-handling, response-parsing logic.
**Recommendation:** Refactor into a single generic `_send<T>()` method.

## P2 — UI/Naming Inconsistencies

### P2-001: No design token system for spacing
**Files:** All 7 screen files
**Description:** Raw `SizedBox(height: X)` literals used with values: 8, 12, 16, 20, 24, 32. Same screen sometimes uses different values for the same purpose.
**Recommendation:** Create `lib/core/theme/spacing.dart` with tokens: `Spacing.sm(8)`, `Spacing.md(12)`, `Spacing.lg(16)`, `Spacing.xl(20)`, `Spacing.xxl(32)`.

### P2-002: Hardcoded color in SignInScreen
**File:** `lib/features/auth/presentation/sign_in_screen.dart` (line ~50)
**Evidence:** `color: Color(0xff00695c)` — duplicates the seed color.
**Recommendation:** Use `Theme.of(context).colorScheme.primary`.

### P2-003: DashboardPage section header has no text style
**File:** `lib/features/business/presentation/business_home.dart` (line ~120)
**Evidence:** `const Text('အမြန်လုပ်ဆောင်ရန်')` — plain Text, no `textTheme` reference. Every other screen uses `textTheme.titleMedium` for section headers.
**Recommendation:** Apply `textTheme.titleMedium` or extract `SectionHeader` widget.

### P2-004: Empty state messages lack styling
**Files:** `ticket_sales_page.dart`, `cargo_worklist_page.dart`
**Evidence:** "Booking မရှိသေးပါ။", "Cargo shipment မရှိသေးပါ။", "လက်မှတ်မရှိသေးပါ။" — all plain `Text()` with no `bodyMedium`, no muted color, no centering.
**Recommendation:** Extract `EmptyStateCard` widget with consistent styling.

## P3 — Other Observations

### P3-001: Key pattern inconsistency in dropdowns
**Files:** `counter_booking_page.dart`, `cargo_acceptance_page.dart`, `payment_decision_page.dart`
**Description:** Some dropdowns use `key: ValueKey(...)`, some use `initialValue` without key, some use neither. No consistent strategy for widget identity preservation across rebuilds.
**Recommendation:** Standardize: use `key: ValueKey(item?.id)` for all dropdowns that affect subsequent widgets.

### P3-002: No permission scope model
**File:** `lib/features/auth/application/session_controller.dart`
**Description:** `hasPermission()` checks a flat `Set<String>`. The architecture spec defines scoped permissions (tenant-wide, branch, terminal, counter, assigned trip).
**Recommendation:** Add `hasPermission(perm, scope: Scope.branch)` signature when scope model is designed.

### P3-003: Three unused dependencies with future value
**File:** `pubspec.yaml`
**Items:** `mobile_scanner`, `sqflite_sqlcipher`, `uuid`
**Description:** These are declared but unused. They add ~4 MB to binary for zero benefit. The scanner and offline database will be needed in future sprints.
**Recommendation:** Remove now, re-add when actively implementing those features.

### P3-004: No Flutter tests in CI
**File:** `.github/workflows/backend-ci.yml`
**Description:** CI pipeline tests only the backend. Flutter code has no automated validation.
**Recommendation:** Add `flutter test` step to CI. The single existing test file is the default template and does nothing meaningful.

### P3-005: No client-side error type hierarchy
**File:** `lib/core/network/api_client.dart`
**Description:** Single `ApiException` class with a `message` string. No distinction between network errors, validation errors, auth errors, server errors.
**Recommendation:** Create `NetworkException`, `ApiException(code, detail)`, `AuthException`, `ValidationException`.

### P3-006: Non-functional QuickAction cards
**File:** `lib/features/business/presentation/business_home.dart`
**Description:** `_QuickAction` has `onTap` parameter but it's never set. Three cards render with arrow icons but do nothing on tap.
**Recommendation:** Either implement the navigation or remove the trailing arrow icon to avoid confusing users.
