# AI Prompt — MVP Acceptance and Release Readiness

Act as a product owner, QA lead, release manager, security lead, SRE, and operations manager.

Create the authoritative **MVP Acceptance Criteria and Release Readiness Standard** for HBT.

## Include

1. Product acceptance criteria by MVP journey
2. Module-level acceptance criteria
3. Data and migration acceptance
4. Offline and synchronization acceptance
5. Security and tenant-isolation acceptance
6. Performance and reliability acceptance
7. Accessibility and localization acceptance
8. Backup, restore, disaster-recovery, and rollback acceptance
9. Monitoring, logging, alerting, and audit acceptance
10. Documentation, training, support, and runbook acceptance
11. Known-defect policy
12. Pilot entry and exit criteria
13. Production go/no-go checklist
14. Post-release verification and hypercare

Each criterion must be objective, testable, traceable, owned, and accompanied by required evidence. Separate mandatory release blockers from waivable risks, and define who may approve a waiver.

Do not claim readiness without evidence. Do not include implementation code.
